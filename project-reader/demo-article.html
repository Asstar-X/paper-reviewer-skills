我实测了一款刚开源的人声分离神器，这效果真的有点把我惊到了

今天想跟大伙聊个特别有意思的事情。

前两天我在整理一段之前录的线下访谈音频，背景里不仅有咖啡厅滋啦滋啦的磨豆机杂音，还有旁边桌客人大声聊天的声音，混成一团。

我当时用手头的两款剪辑软件自带的降噪跑了一遍，结果修出来的人声，要么像是在铁皮桶里说话，发闷得不行；要么直接把说话人的喘气声、笑声全当噪音一刀切了，听着像个没有感情的 AI 假人。

正好那天晚上刷开源社区，看到 Inworld 团队开源了一个叫 voice-isolator 的新项目，号称能做到 48kHz 全频带高清人声分离，实时通话延迟还能压到 63 毫秒。

我顺手拉下他们官方提供的测试音频与在线 Demo 跑了一圈，听完的那一瞬间，确实有点被惊艳到了。

一句话说人话：它到底干了啥？

如果用大白话解释，它就像是一张“极其灵敏的数字人声滤网”。不管你的录音里有多吵的背景音乐、环境杂音甚至是旁边别人的闲聊，它能像拿镊子一样，把属于主角的声音干干净净挑出来，剩下的垃圾全部过滤掉。

1. 两款模型各司其职：放出两套权重，离线版 voice-isolator-v1（64M）追求极致音质，实时版 realtime（58M）延迟仅 63 毫秒。

2. 反向操作变“纯伴奏提取器”：提取人声与原音频完全对齐、音量一致，用原音频减去提取人声即可得到干净伴奏。

3. Apache-2.0 免费商用：代码、权重与 VIBE 评测榜单全部开源，并提供开箱即玩的在线演示。

以前大家卡在哪？作者为什么选这条路？

以前我们做音频降噪，最大的痛苦就两个字：失真。

过去主流的降噪模型基本都跑在 16kHz 的采样率上，也就是普通电话通话的水平。一旦拿到录音棚或者高清视频的 48kHz 音频，高频那些细腻的空气感、唇齿音全被抹平了。

补充背景 · 48kHz 到底是个啥？

平时打电话用的 8kHz 或 16kHz 音质，能听清说什么但干瘪单薄；而 48kHz 是广播、电影和高清音乐的工业标准，能把说话时的呼吸起伏与细节完整留住。

Inworld 这次没有盲目去堆几十亿参数的臃肿大模型，而是把整段音频切成了 46 个精细的频段，用 Transformer 注意力机制和 Mamba 架构交替配合，把实时版延迟压到了 63 毫秒。

更狠的是训练数据。他们特意喂了大约 1 万小时真实复杂场景的数据——包含小声耳语、大笑、唱歌、喘息与各种生活噪音，把模型练成了“只去杂音、保留原汁原味”的工程工具。

想体验的话，怎么上手？

如果手头有嘈杂音频想亲自试一试，官方提供了很直观的体验途径：

1. 小白最省事路径（免安装在线玩）：官方在 GitHub 上配了可交互在线演示 Demo，上传音频即可当场听前后对比。

2. 开发者本地部署：完整源码、环境依赖与模型权重均托管在 GitHub 和 Hugging Face。

泼点冷水

根据官方披露的信息和技术本身的约束，有几个明显的局限，用之前心里必须有数：

第一，只管“擦灰尘”，不管“修破损”。如果原始录音本身因为麦克风太差、电话压缩太狠导致发闷丢高频，模型不会把音质凭空变好，只会把那段“发闷的声音”分离出来。

第二，分不清“谁是谁”。它不是声纹锁定模型。如果两个人同时说话，它会留下声音更大的那个，音量接近时则会一起留下来。

第三，硬件适配还没做全，且只吃单声道。官方目前重点测试了 CPU 和企业级计算卡（A100/H100/B200），消费级显卡未做全覆盖测试；且只支持单声道输入，立体声素材需先拆开处理。

但无论如何，在开源音频领域能把 48kHz 全频带保真和 63 毫秒延迟做到这个水准，还用 Apache-2.0 免费商用，已经是非常实在的一次技术普惠。

做播客剪辑、短视频配音，或者实时语音交互产品的朋友，非常值得收藏下来先试听对比一下。
